# 铅槽条排料台（Lead Came Nesting Bench）

彩绘玻璃工作室用的**纯前端**铅槽条精确排料台。从空仓库起步：录入每根条材的
长度、头部修齐量、疵点闭区间，以及不可拼接裁片的长度与锯缝宽度；把裁片拖到
指定条材上即可**锁定**。浏览器内做精确搜索，先最少启用条材，再最小化短余料，
并用可缩放 SVG 落刀图交付可执行方案，支持方案 JSON 下载。

## 为什么需要它

- **最长料先放（FFD/best-fit 类）贪心会提前报废**：存在明明有解却被判无解的
  情形。本仓库内置一个由穷举得到的最小反例
  （容量 14，件 8,8,6,5,4,4,3,2,2；最优 3 条，贪心开第 4 条），
  端到端测试会复现该反例并验证精确搜索只用 3 条。
- **漏算锯缝会让纸面方案无法落刀**：裁片右侧锯缝同样占格且不得碰不可用格。
  测试覆盖「裁片恰好顶到疵点、锯缝越界 → 必须后移到下一段」的情形。

## 离散模型（0.1 毫米整数倍）

- 所有尺寸只接受 **0.1 mm 的整数倍**，录入非法精度会就地报错。
- 内部以「格」为单位，1 格 = 0.1 mm，全部整数运算，无浮点误差。
- 条材换算长度 `L` 占格 `0 … L-1`。
- 不可用格：头部修齐 `[0, headTrim)` 与每个疵点**闭区间** `[from, to]`
  （占 `to-from+1` 格）。
- 扣除不可用格后得到若干**极大连续可用段**。
- 裁片自起点连续占其长度格，其**右侧锯缝**再占相应格；两者都不得与不可用格
  相交，因此重量 = 裁片长度 + 锯缝，只能整段落进某个可用段（裁片不可拼接）。
- 锁定**只限定条材**，起点仍由求解器选择。
- 在段内，规范方案把裁片按标识升序从段首左叠：把任何两侧皆空的裁片滑到端点
  不会增加余料代价，却单调减小放置三元组，因此最优解总可取此规范形，问题归约
  为带锁的一维装箱。

## 目标层级（字典序优化）

1. 最少**启用条材**数（至少放入一片的条材才算启用）；
2. 启用条材内**短于复用阈值的余段总长**最小（余段 = 扣除裁片与锯缝后的极大
   连续可用段；达到阈值的余段记为「可复用」，不计代价）；
3. 仍并列时，把放置三元组 `(条材标识, 起点, 裁片标识)` 按条材标识、起点、
   裁片标识排列后，取**序列字典序最小**者。

无解时明确报告，**不展示半成品**：

- `lock-capacity`：列出造成容量冲突的锁定条材、锁定裁片、需求与可用格数；
- `total-demand`：总需求（含锯缝）超过全部可用容量，给出双方数字；
- 结构性无解（总容量够但被疵点分割/锁定逼死）给出说明。

搜索超过节点预算时报告 `limit`，同样不展示半成品。

## 界面

- 条材卡：标识、长度、头部修齐、任意多个疵点闭区间；可拖入裁片锁定。
- 裁片区：标识、长度、锁定下拉框；可拖动到条材或拖回解锁区解除锁定。
- 全局：锯缝宽度、复用阈值。
- 所有错误在字段下方就地红底提示；条材/裁片标识各自唯一。
- 结果 SVG：可缩放（＋/－/复位），绘制头部修齐、疵点、裁片、右侧锯缝、
  可复用余段与短余料；蓝线=裁片起点，红线=落刀口，标注每个刀口的毫米坐标；
  另附落刀坐标表与目标值，一键下载方案 JSON。
- 不预置任何硬编码示例答案；所有按钮均有真实行为（无空按钮）。

## 本地开发

```bash
npm ci
npm run dev          # http://localhost:5173
npm test             # 单元 + 端到端（Vitest + Testing Library，jsdom）
npm run diffcheck    # 400 个随机实例与独立暴力枚举器对照 f1/f2/字典序
npm run build        # 类型检查 + 生产构建到 dist/
npm run verify       # 类型检查 + 测试 + 差分对照 + 构建（一次性验收）
npm run preview      # 预览构建产物
```

## Docker Compose

```bash
# 启动静态应用（默认宿主端口 8080，可用 APP_PORT 覆盖）
APP_PORT=9000 docker compose up -d --build
# 浏览器打开 http://localhost:9000

# 一次性验收服务：类型检查 + 全部测试 + 差分对照 + 生产构建，结束即退出
docker compose --profile verify run --rm verify
```

## 目录

```

src/ui/       React + SVG 界面（Editor / ResultView / App）
test/         编辑器校验、几何、求解器、结果图算法测试与端到端反例（同一链路）
scripts/      diffcheck.ts 随机差分对照（暴力枚举基准）

Dockerfile.verify     一次性验收镜像
```

## 方案 JSON 结构

`objective.stripsUsed`、`objective.shortRemnantMm`、`enabledStrips`、
每个 `placements` 的 `stripId/startMm/pieceEndMm/kerfEndMm`、每个 `remnants`
的区间、长度与 `reusable|scrap` 分类，以及规范三元组序列 `triples`。
